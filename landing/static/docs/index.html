PRZEWODNIK / 0.4.0 ALPHA

Uruchom własne
laboratorium testów.

Repozytorium zawiera paczkę Python, osobny landing page i obrazy Docker. Testy nie wymagają dostępu do kodu aplikacji do analizy interfejsu.

1. Instalacja z dostarczonej paczki

python3 -m venv .venv
. .venv/bin/activate
make install
make landing-check

Komendy wykonaj w rozpakowanym folderze projektu. Potrzebne są Python 3.11–3.13, Make oraz Docker z Compose v2. Obrazy i zależności są pobierane podczas budowania.

2. Przetestuj własną aplikację

make check APP=/sciezka/aplikacji \
  APP_IMAGE=python:3.12-slim \
  APP_COMMAND="python -m http.server 8080 --bind 0.0.0.0"

Folder aplikacji jest kopiowany z wykluczeniem typowych sekretów i pamięci podręcznych. Dla konkretnego frameworka podaj właściwe zależności i komendę startową.

3. Wybierz warstwę

WarstwaZadanie
TestQLWykonanie scenariuszy shell i WWW przez publiczne API.
CDP / PlaywrightScreenshoty, geometria DOM i macierz urządzeń.
LiteLLMOpcjonalna ocena obrazu i wizualnego rezultatu.
OpenCV / YOLOWzorce obrazu i regiony elementów; nie automatyczna diagnoza błędu.

4. Kontrola wyników

Raporty powstają w katalogu artifacts. Kod wyjścia 0 oznacza brak potwierdzonych naruszeń w ukończonym audycie; 1 oznacza naruszenia; 2 oznacza niekompletność lub błąd konfiguracji. Walidacja scenariusza bez wykonania ma oddzielny status.

LLM i prywatność

Ustawienia providerów są w jednym pliku .env. Transfer do zdalnego modelu wymaga LLM_ALLOW_REMOTE=1. Używaj danych syntetycznych. Obserwacje LLM mają status kandydata, bez prawa wykonywania poleceń.

Pełna dokumentacja, status testów i instrukcja publikacji PyPI znajdują się w paczce projektu. Ta strona nie oznacza, że publikacja PyPI lub wdrożenie domeny zostały już wykonane.
